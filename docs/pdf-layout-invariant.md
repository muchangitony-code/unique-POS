# PDF layout invariant

The old invoice/quotation renderer mixed implicit PDFKit cursor flow (`doc.text()` advancing `doc.y`) with explicit `(x, y)` drawing and reused hard-coded coordinates. It also rendered table columns by ad-hoc x positions, so wrapped descriptions changed visual row height without moving the other cells, causing header collisions, drifting totals and detached table rows. The stable engine now has one page geometry definition and one `COLUMNS` definition; every text draw receives an explicit box, every row height is measured with `heightOfString()`, all cells in a row share the same y, and each block returns its ending y. Pagination is calculated from measured row heights and reserves the complete totals/notes/terms block before the final page. This invariant prevents a block from relying on stale `doc.y` or a hard-coded column position.
